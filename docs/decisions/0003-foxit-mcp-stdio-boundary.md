# ADR 0003: Pin Foxit preparation to the official Python MCP server over stdio

- Status: accepted
- Date: 2026-08-25

## Context

Foxit maintains an active Python MCP server and labels its TypeScript server as
deprecated. The Python entrypoint defaults to stdio. Although an HTTP transport
flag exists, the same source currently warns that HTTP mode is still being
implemented.

## Decision

SignLatch uses the official Python server as an external, pinned dependency and
connects with the official TypeScript MCP SDK over stdio. It does not copy Foxit
source into this repository. The application exposes only a small reversible
tool allowlist and keeps eSign outside the MCP client.

Tool inputs are generated by deterministic application code. Untrusted document
text cannot choose a tool or supply a filesystem path. Download paths are
created inside an application-owned ephemeral directory. Secrets are passed to
the child process without being included in provenance.

## Consequences

- Local and container deployments need Python 3.11+, `uv` and the pinned Foxit
  package in addition to the Node.js application.
- A serverless runtime that cannot spawn a child process is not an eligible M3
  deployment target.
- We can test the authority boundary without credentials, but the milestone
  remains incomplete until a real Foxit operation is captured as evidence.
